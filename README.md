# Пассивные Nuclei-шаблоны для проверки PHP2Shell

Набор предназначен для первичной оценки подверженности PHP двум уязвимостям:

- CVE-2026-109618;
- CVE-2026-109619.

Шаблоны выполняют по одному обычному HTTP GET-запросу к каждой указанной конечной точке и анализируют признаки PHP и раскрытую версию. 
Они не отправляют multipart/OOM-payload, не проверяют повреждение сессии, не выполняют команды и не воспроизводят эксплуатацию уязвимостей.

Используйте шаблоны только для систем, на проверку которых у вас есть разрешение.

## Состав набора

| Шаблон | Что означает результат |
|---|---|
| `php2shell-affected-upstream-version` | Обнаружена раскрытая upstream-версия PHP ниже исправленного порога |
| `php2shell-unsupported-branch` | Обнаружена неподдерживаемая ветка PHP, для которой требуется обновление или отдельная проверка патча поставщика |
| `php2shell-php-version-unknown` | Есть признаки PHP, но полную версию `x.y.z` определить не удалось |
| `php2shell-php-application-indicator` | Обнаружено приложение или фреймворк экосистемы PHP; версию PHP необходимо проверить отдельно |

Четвёртый шаблон распознаёт 1С-Битрикс, Drupal, WordPress, Joomla, Nextcloud,
Magento / Adobe Commerce, Laravel, Symfony и MODX. В результате указывается
имя сработавшего matcher-а, например
`[php2shell-php-application-indicator:drupal]`.

Для поддерживаемых веток используются следующие исправленные upstream-версии:

| Ветка PHP | Первая исправленная версия |
|---|---:|
| 8.2 | 8.2.35 |
| 8.3 | 8.3.36 |
| 8.4 | 8.4.27 |
| 8.5 | 8.5.12 |

К неподдерживаемым относятся обнаруженные ветки PHP 5.4–5.6, 7.x, 8.0 и 8.1.

Все находки имеют уровень `severity: info`. Это сделано намеренно: результат
является пассивным определением версии или технологии, а не подтверждением
эксплуатации. Заголовок с версией может быть устаревшим, добавленным прокси либо
не учитывать backport исправления от поставщика.

## Требования

- Nuclei 3.11.1 или новее;
- сетевой доступ к проверяемым endpoint;
- разрешение владельца систем на сканирование.

Проверить установленную версию:

```bash
nuclei -version
```

## Проверка шаблонов

Из корневого каталога, содержащего папку `nuclei`:

```bash
nuclei -validate -t nuclei/
```

Для PowerShell:

```powershell
nuclei -validate -t .\nuclei\
```

## Запуск

Проверка одного точного URL с коротким выводом:

```bash
nuclei -u https://corp.example:443/ -t nuclei/ -silent -nc
```

Проверка списка целей:

```bash
nuclei -l targets.txt -t nuclei/ -silent -nc
```

Пример `targets.txt`:

```text
corp.example
192.0.2.10
portal.example:8877
https://portal.example:8877/
```

Nuclei принимает URL, доменные имена, IP-адреса и `host:port`. Если схема не
указана, встроенное HTTPX-пробирование определяет доступный HTTP- или
HTTPS-endpoint. Для `portal.example:8877` протокол определяется на указанном
порту. Не используйте параметр `-no-httpx` (`-nh`), если рассчитываете на такое
автоматическое определение.

Автоматическое пробирование выбирает доступный URL, но не гарантирует запуск
шаблонов по всем сочетаниям схем и портов. Если HTTP и HTTPS нужно проверить
независимо либо требуется охватить нестандартные комбинации, перечислите точные
endpoint явно:

```text
http://corp.example:80/
http://corp.example:443/
https://corp.example:80/
https://corp.example:443/
```

Markdown-ссылки вида `[https://corp.example](https://corp.example)` следует
предварительно заменить обычными URL.

## JSONL-отчёт

Компактный машиночитаемый отчёт без сырых HTTP-ответов и исходного текста
шаблонов:

```bash
nuclei -l targets.txt -t nuclei/ -jsonl -omit-raw -omit-template -o php2shell-nuclei.jsonl
```

Не удаляйте `-omit-raw`, если отчёт будет передаваться третьим лицам без
предварительной проверки: сырые ответы могут содержать cookies, токены и другие
чувствительные данные.

## Интерпретация результата

Пример:

```text
[php2shell-affected-upstream-version:detected-php-version] [http] [info] https://host.example ["8.2.20"]
```

Здесь:

- `php2shell-affected-upstream-version` - сработавший шаблон;
- `detected-php-version` - extractor, который вывел найденную версию;
- `http` - протокол шаблона Nuclei;
- `info` - информационный уровень достоверности пассивной находки;
- URL - проверенный endpoint;
- `8.2.20` - обнаруженная версия PHP.

Рекомендуемая трактовка результатов:

- `affected-upstream-version` - запланировать обновление и подтвердить реальную
  версию PHP на сервере или в контейнере;
- `unsupported-branch` - перейти на поддерживаемую ветку либо получить
  документальное подтверждение backport исправлений поставщиком;
- `php-version-unknown` - определить версию локально: `php -v`, через пакетный
  менеджер, образ контейнера или инвентаризацию узла;
- `php-application-indicator` - приложение обычно использует PHP, но находка не
  содержит версию runtime и не подтверждает подверженность PHP2Shell;
- отсутствие результата - не доказывает отсутствие PHP или уязвимости: сервер
  мог не раскрыть технологию, вернуть другой ответ либо отфильтровать запрос.

## User-Agent и фильтрация запросов

Шаблоны намеренно не задают фиксированный `User-Agent`, поэтому Nuclei
использует своё стандартное поведение. Это снижает вероятность блокировки по
постоянной сигнатуре сканера.

Если необходимо маркировать согласованное сканирование, используйте отдельный
заголовок, не заменяя `User-Agent`:

```bash
nuclei -l targets.txt -t nuclei/ -silent -nc -H "X-Authorized-Scan: php2shell-audit"
```
